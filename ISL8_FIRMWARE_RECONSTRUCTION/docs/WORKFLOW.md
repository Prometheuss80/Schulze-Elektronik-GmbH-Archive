# Reconstruction process

1. **Hardware capture:** A Teensy 4.1 ROM emulator monitors execution-address accesses in the Schulze ISL8-936G. A Raspberry Pi 5 logger records USB events. Original tools: `001_LOGGER.py` and the optional fast binary capture/converter tools.
2. **Integrity and capture handling:** `002_TEST.py` validates event syntax and sequence numbering. `003_SPLIT.py` / `004_JOIN.py` are optional for long captures; the public release aligns their segment indices to three digits (the original `003_SPLIT.py` is kept in `docs/original_scripts/`).
3. **Address maps:** `005_RESULT.py`, `006_DATA.py`, `007_OUTPUT.py` build maps of observed addresses and extracted firmware bytes.
4. **Optional inspection:** `008_DEDUP.py` removes repetitive records; `009_CHECK.py` provides user-data checks; `010_SEARCH.py` scans ASCII sequences.
5. **Code/data and time trace:** `050_BLOCK_1B_PC.py`, `051_TIME_TRACE.py`, `052_TRACE.py` derive address ranges and time-based CODE/DATA classifications.
6. **Assembly reconstruction:** `101_RECONSTRUCTION_FINAL.py` combines trace, opcode definitions `C500.txt`, register definitions `header.txt`, and user-confirmed address lists to create `Reconstruction.a51`.
7. **Post-processing:** `102_FILL_FINAL.py` fills unobserved bytes; `103_RENAME_FINAL.py` names registers; `104_LABEL.py` and `105_JUMPS.py` generate labels; `106_STRIPPED.py` removes unnecessary labels.
8. **Validation:** `107_CHECK_FINAL.py` checks code/data overlap; `108_PROCESS_FINAL.py` describes unobserved ROM ranges; `109_DIFF_FINAL.py` compares a Keil-created `Objects/Reconstruction.hex` to the input BIN; `110_SERVER_FINAL.py` creates coverage visualization.
9. **Specialized tools:** Scripts numbered `111` and above support additional search, cleanup, analysis and specific experiments; see the script index.

**Inputs:** `fw850en.bin`, `LOG_ISL8_ALL.txt`, `header.txt`, `C500.txt`, `FINAL_USER_CODE.txt`, `FINAL_USER_DATA.txt`, `name_reg_bit.txt`, `name_reg_data.txt`, and optional user clean code/data lists. Most other intermediate artifacts are generated by tools. The demo contains only artificial ROM content. Do not replace the demo file with proprietary firmware in a public repository.

## Primary reconstruction objective: separating CODE and DATA

The decisive benefit of the address/time-trace system is locating the executed code regions instead of blindly disassembling every ROM byte. `051_TIME_TRACE.py` / `052_TRACE.py` participate in temporal classification; `FINAL_USER_CODE.txt` / `FINAL_USER_DATA.txt` supply manual confirmations. `110_SERVER_FINAL.py` visualizes this division. Unobserved bytes require further investigation rather than automatic classification as DATA. See [ACQUISITION](ACQUISITION.md) and [coverage map](images/coverage_map.png).
